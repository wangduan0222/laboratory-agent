# 架构与工程设计

[返回项目介绍](../README.md)

本文为实现的高层说明，省略内部配置、模型提示词、部署地址与业务数据。

## 1. 请求入口与编排

前端通过 FastAPI 接入对话、知识库、任务和报告功能。LangGraph 根据请求与会话上下文组织文档查询、结构化结果查询或报告准备流程；Skills 提供相应任务的操作约束。

模型的作用是理解请求、选择受支持的工具和组织回答。后端承担数据访问、结果校验与文件生成，不把任意模型文本直接作为业务操作执行。

对话使用 SSE 传递执行状态，用户可以看到查询、整理、校验等步骤。执行状态是系统实际事件，不是模型内部思考过程。请求标识与会话记录用于关联一次请求及其结果。

## 2. 文档入库

```mermaid
flowchart LR
    F[上传文件] --> T[创建任务]
    T --> P[解析 / OCR]
    P --> C[章节与分块]
    C --> D[保存解析结果和元数据]
    D --> E[向量化]
    E --> I[索引同步]
    I --> V[更新可检索状态]
```

- PDF、Word 和 Markdown 走文档解析路径；Excel 检测结果进入结构化导入路径。
- 较长 PDF 的 OCR 按片段处理，降低整份文件同时处理的资源压力；这不意味着内存和文件大小没有上限。
- 解析产物、任务阶段和文档版本分别记录，为中断恢复及后续索引处理提供依据。
- 解析成功不等于向量入库成功，因此分别展示解析状态和向量准备情况。
- 对可能产生费用的 OCR 或模型调用保留明确的重试控制。

## 3. 检索与证据组织

文档问答包含候选召回、业务范围过滤、证据组织和回答生成等环节。以下按职责说明，而非逐行执行顺序。

| 环节 | 解决的问题 |
| --- | --- |
| 范围限定 | 确定知识库、文档类型和有效文档范围 |
| 混合召回 | 结合向量语义相似度与应用层 BM25 关键词信号 |
| 融合与可选重排 | 调整候选相关性和最终排序 |
| 证据组织 | 关联章节与正文，减少只有标题或重复片段占用上下文 |
| 预算控制 | 在模型输入空间、输出预留及必要提示约束下安排证据 |
| 生成与校验 | 围绕问题回答，保留可追溯来源和证据不足提示 |

### 为什么不只增加 Top K

Top K 限制的是数量，不保证不同问题项都被覆盖。多个相近片段可能挤占唯一能回答某个子问题的正文；只扩大输出上限也不能恢复上游已被排除的证据。

因此项目区分候选数量与最终送模预算，并对章节正文、方法分组和多项问题的证据覆盖进行处理。该机制改善证据分配，但不能保证所有问题都能得到完整答案，仍需要通过固定案例检查缺项与偏题。

### PostgreSQL 与 Milvus 的关系

PostgreSQL 管理文档身份、任务状态、分块元数据和业务记录，也提供 pgvector 能力；Milvus 承担独立向量检索职责。两者属于不同存储职责，不应视为完全相同的数据副本。

向量命中还需要关联 PostgreSQL 中的有效状态。索引残留、版本不一致或向量未准备完成，都需要显式识别和处理，不能只看向量库记录数判断文件可用性。

## 4. Excel 结构化查询

```mermaid
flowchart LR
    Q[自然语言与会话上下文] --> S[提取批次及查询条件]
    S --> V[校验目标与字段]
    V --> D[查询结构化记录]
    D --> A[确定性筛选与统计]
    A --> O[摘要 / 明细 / 报告入口]
```

Excel 导入后保留样品、元素、结果状态和原表位置等信息。查询使用结构化记录进行筛选与计算，避免把整份表格送给模型再让模型自行数行。

“检出”依据导入后的结果语义处理，明确的未检出标记与数值结果需要区分，空白和未知状态也不应直接算作检出。统计和报告筛选应使用一致的数据口径。

目标可以来自本轮请求或明确的会话上下文；若无法唯一确定文件或批次，再提示用户确认，避免在已经提供目标时重复要求选择。

## 5. 报告生成

1. 识别生成报告的意图，并解析批次、检出范围、数量等条件。
2. 解析目标批次，准备或继续已有草稿。
3. 选择整批、仅检出、原表顺序前 N 条或手动勾选记录。
4. 核对送样信息、日期等字段及最终记录范围。
5. 由后端校验范围并固定数据快照，使用模板生成 Word 文件。
6. 在关联聊天消息中更新结果，提供受控下载入口。

N 为用户指定的正整数，不固定为 10；当可用记录不足或所选记录无效时，需要明确处理，而不是静默换一批数据。手动选择与最终导出使用同一记录范围。

草稿是生成前的业务状态，不需要作为标题字段打印在最终报告中。报告首页展示基础信息，后续页面延续结果表；系统生成文件不代替人工审核与正式签发。

## 6. 任务、评测与可观测性

- 文档任务和评测任务由独立 Worker 执行。
- PostgreSQL 保存持久化业务状态；Redis 用于队列、租约与缓存等运行协调。
- 任务区分排队、处理中、完成、失败、取消和中断，便于判断问题发生在哪个阶段。
- 评测记录问题、配置与资料快照，以便比较不同运行结果。
- 检索指标、答案生成结果与评测器错误分别记录，不把它们混为一个成功率。
- 评测进度达到 100% 只代表题目处理结束，不代表全部答对或全部评分成功。
